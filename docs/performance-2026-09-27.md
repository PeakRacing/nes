# SDL 流畅度与 MCU 效率分析

## 后续优化实测

已实现 PRG 总线读取提前判断、完整背景 tile 的 8 像素常量移位展开，以及 CHR bank 号合法时跳过取模、LRU 候选无望时跳过活动映射扫描。背景的细滚动边缘仍走逐像素路径；mapper 取数回调顺序保持一致。核心优化未新增持久 RAM。

Windows x64 Release，同一《激龟忍者传2》6000 帧、模块计时关闭、完整哈希关闭，三次均值的中位数：

| 配置 | 优化前 | 优化后 | 耗时减少 | 有效堆峰值 |
| --- | ---: | ---: | ---: | ---: |
| 普通 32 位全帧 | 227.370 us | 198.837 us | 12.5% | 786772 B |
| RGB565 半帧流式，6/12 槽 | 261.293 us | 254.112 us | 2.7% | 131444 B |
| RGB565 半帧流式，8/32 槽 | 261.293 us（原 6/12） | 220.499 us | 15.6% | 168396 B |

单轮交叉检查：《沙罗曼蛇》212.706 → 187.112 us，《沙罗曼蛇2》220.707 → 187.573 us。桌面最大帧耗时受进程调度影响，未据此宣称峰值改善；以上不能直接推导 MCU 收益。

缓存扩容将 6000 帧 PRG miss 从 96322 降到 82002，CHR miss 从 99875 降到 290；额外有效堆 36952 字节。默认缓存容量不变，通过端口宏选择更大的容量。

CPU 提前判断单独测量约减少 5% 整帧耗时，背景展开在其基础上再减少约 8%；bank/LRU 微优化未单独得到可靠的速度增益数字。193 张普通严格语料回归 HASH_DIFF 0 / REGRESSED 0，普通/流式/跳帧完整单测均 37 ran / 0 failed。SDL 优化前后 300 帧哈希一致；两种缓存容量下《激龟忍者传2》《沙罗曼蛇》各 6000 帧全输出像素与音频字节累计哈希一致。

以下保留前一阶段测量，时间不同，勿将单轮数值直接与上表混算。

### 流式回归补充（2026-09-28）

以优化前源码单独构建流式测试程序，同样运行本地 193 张 ROM。优化后除两份《L'Empereur》外，其余 191 张的逐帧哈希链、verdict、首次渲染帧均与优化前一致。

两份《L'Empereur》暴露了原有 MMC5 扩展背景读取问题：以完整 CHR ROM 地址直接访问仅 12 KiB 的缓存，产生越界与不稳定结果。现已通过缓存获取对应 1 KiB 页中的 tile，保持原 pattern 映射不变；修复后这两份 ROM 与普通构建基线哈希相同。新增测试覆盖缓存容量以外的 tile 读取，并检查原映射及映射内容不被替换。

流式构建对普通构建的严格基线仍未全通过：18 项既有 HASH_DIFF，以及 Death Race / Super Mario Bros. + Tetris + Nintendo World Cup 两项既有 blank。它们与优化前流式结果一致，不更新普通构建基线掩盖差异。故验收结论为普通严格回归通过、流式相对优化前无新增退化，并修复两份 MMC5 ROM；不宣称全部流式 ROM 与普通构建一致。

本次使用 Windows x64 Release、相同 ROM《激龟忍者传2》测量。桌面耗时不能换算成 MCU 帧率。

## SDL 帧调度

核心无界面运行平均约 0.225 ms/帧，远低于 60 Hz 的 16.67 ms 预算。SDL 原实现用整数毫秒睡眠一次，不复查截止时间；渲染器没有启用垂直同步，应用提交与显示刷新也可能不一致。

修复：等待后重新检查截止时间，最后不足 2 ms 时让出调度并复查；PAL 使用 50 Hz。最后短时段的轮询可能增加桌面 CPU 占用，MCU 端不受该 SDL 修改影响。

同一游戏运行 300 帧（299 个间隔）：

| 提交间隔 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 平均 | 16.668 ms | 16.664 ms |
| P95 | 17.679 ms | 16.819 ms |
| 最大 | 18.796 ms | 17.862 ms |
| 超过 20 ms | 0 | 0 |

300 帧哈希完全一致。短测未复现明显长帧，不能据此断定用户所有游戏都已流畅。VSync、显示刷新率、窗口合成器造成的实际呈现节奏仍需针对用户 ROM 验证。

## 核心热点

1800 帧，模块计时开启时，普通配置 CPU 42.5%、背景 37.1%、精灵 8.3%、APU 1.0%。计时本身有成本，整体速度比较使用 `--regions 0`，模块占比仅用于定位。

流式配置 PRG miss 26728 次、CHR miss 33527 次，相当于每模拟帧约 14.8 次 8 KiB 读取和 18.6 次 1 KiB 读取。CPU 区域包括由 bank 切换触发的同步 I/O，不能把全部 CPU 区域时间归因于指令解释器。MCU 上应优先测单次读盘延迟、每帧 miss 峰值，并比较更大的缓存或 Flash 直接映射。

普通配置有效堆峰值 786772 字节；RGB565、半帧、流式、跳帧配置 131444 字节。后者设置 `NES_FRAME_SKIP=1`，60 Hz 模拟只输出约 30 个新画面/秒。这两种配置同时改变多项参数，不能作为单项优化收益对照。堆统计不含栈、分配器及平台内部缓存。

## 优化排序

1. 桌面先验证帧调度和呈现节奏；核心更快不一定消除显示抖动。
2. MCU 流式存储优先减少缓存 miss；测试缓存槽位与 RAM 的交换收益，保留 mapper 的取数副作用。
3. 背景绘制考虑按 tile 解码、合并不透明度计算；逐像素遮罩外移已试验，普通配置 225.3 → 226.3 us，流式配置 270.3 → 267.6 us，变化不足以证明稳定收益，已撤回。
4. CPU 检查总线读取和 mapper 回调路径，按实际板子保留普通映射快路径。
5. APU 在桌面占比小，暂不增加相位缓存状态；无硬件除法的 MCU 仍需独立测量 64 位除法成本。

测试：普通 37 ran / 0 failed / 3 skipped；流式 37 ran / 0 failed / 1 skipped；跳帧 PPU 9 ran / 0 failed。修正了跳帧测试中背景与精灵共用图块导致的误判，使用独立图块验证绘制/跳帧两种情况下的命中与不命中。

严格 ROM 回归：当前本地 193 张（基线另有 2 张本地缺失），REGRESSED 0 / HASH_DIFF 0。SDL 生产与测试目标均已成功构建。
